# Matches

Matches are created from scheduled fixtures. Creation freezes the tournament's current rules version, format, team snapshots, schedule and innings/over limits into a tenant-owned match record. At match start, the active roster player IDs for both teams are also frozen for event attribution. A unique tenant/fixture index prevents multiple match aggregates for one fixture. Starting a match requires an organization owner/admin, the scheduled time to have arrived, an explicit toss winner and a BAT/BOWL decision; the fixture and first innings transition in the same transaction.

Organization owners/admins assign active tenant members as match scorers and can revoke assignments. Removing a current lease holder revokes the lease and increments its epoch. Each innings has one scorer lease with a monotonically increasing `leaseEpoch`. The assigned scorer or an organization owner/admin can acquire an expired lease. An active lease takeover requires owner/admin authority and a reason; incrementing the epoch fences queued events from the prior scorer. Renewals preserve the current epoch. Lease expiry is server-time based.

Tenant match and score reads require membership. Public tournaments also expose allowlisted fixture-ordered match snapshots and per-match score snapshots; they contain team details, configured rules, innings totals and results, but no player identity or scorer/tenant data. T10/T20/ODI scorecards determine winners; a successful chase ends on the target ball. An owner/admin must resolve a tied score when policy is SUPER_OVER or REPLAY; the tiebreak innings themselves are not yet modeled. Owner/admins explicitly adjudicate Test and custom match results and may record no-result outcomes. Match completion, fixture completion and standings updates are transactional. Win/tie/no-result points default to 2/1/1 and are configurable in tournament rules then frozen into each match. T10/T20/ODI net run rate is updated from completed innings; Test and custom matches do not affect NRR. Public match changes publish advisory SSE version notices; clients reload snapshots after connect, reconnect or a notice. Schedule changes remain future work. See `docs/openapi/matches-scoring.yaml` for the current contract.
