# Auctions

The initial slice creates one auction per tournament after registration closes. It freezes tournament rules and auction settings, opens an integer-credit purse account and initial ledger entry for each active team, and allows only authorized team bidders to be assigned. A bidder must already be an active tenant member with the team-scoped `BIDDER` role. Organization owners/admins and team owners manage bidder assignments.

An owner/admin can approve a deterministic pool from approved tournament registrations that do not already have an active direct roster entry. Pool approval requires at least one active bidder per team, snapshots only allowlisted cricket-profile fields, saves the seed/algorithm, and locks direct roster edits so purse roster counts remain stable. General auction reads omit purse budgets; only organization admins, team owners, and assigned bidders can read account balances within their scope.

Purse values use integer internal credits and are not currency or stored value. The denomination label is display-only pending ADR-007. A draft with no approved pool can be cancelled with a reason; cancellation releases the direct-roster lock and preserves its account history. Setup and pool changes write audit and outbox records transactionally.

The live slice supports schedule, start, pause, and resume transitions; one open lot at a time; bounded unsold reoffers; version-checked bids with UUID idempotency keys; integer purse reservations and releases; configurable anti-sniping extensions; and timer-gated finalization. Pausing also marks the current lot paused and preserves its remaining timer duration for resume. A sold result commits the winning amount and creates or restores an `AUCTION_RESULT` roster entry in the same transaction. Each purse mutation appends a sequence-numbered ledger entry; audit and outbox events are committed with the domain changes. The independent `pnpm auction-worker` process opens the first/next lot, finalizes expired lots, and completes exhausted auctions. API operators can also trigger these actions manually; user and system actors are distinguished in audit, purse-ledger, result, and roster history.

The implementation requires a MongoDB replica set or sharded cluster that supports transactions. Bid writes serialize through the current lot and purse-account documents; callers must refresh the lot version after a stale-version response. The bidder's client supplies a UUID idempotency key and must reuse it only for retries of the same bid intent. A result is unique per lot attempt, and reoffers increment the attempt number while preserving the original player snapshot and lot number. Tenant bid history omits bidder identity and idempotency data. Public snapshots/results require a public tournament, return only allowlisted fields, and resolve player visibility against the current profile so private profiles are omitted. Public reads use `Cache-Control: no-store` and a process-local limit of 120 requests per minute per IP; use a shared rate-limit store before deploying multiple API replicas. Worker finalization delay is bounded by `AUCTION_TIMER_POLL_MS` during healthy operation; persistent settlement invariant failures require operator review. Public auction SSE delivery is implemented through the realtime process; delivery is advisory and clients must reload the public snapshot on connection, reconnect, or a `snapshot_required` notice. Authenticated Socket.IO rooms, shared scale-out stream limits and production concurrency/operations evidence remain future work.

HTTP contract: `docs/openapi/auctions.yaml`.
